# 네이버 블로그 연예 이슈 자동화 전략

## 방향 전환

기존 방식은 하루 연예뉴스를 한 글로 요약하는 티스토리형 초안이었다. 앞으로는 네이버 블로그에 맞춰 `1개 기사/1개 이슈 = 1개 포스트` 방식으로 바꾼다.

목표는 단순 요약이 아니라, 특정 인물/작품/사건 키워드로 검색한 사용자가 바로 읽을 수 있는 개별 이슈 글을 지속 발행하는 것이다.

운영 목표는 `완전 자동화`다. 사람이 매번 고르는 초안 시스템이 아니라, 수집부터 이미지 선택, 글 작성, 검증, 예약/발행까지 자동으로 이어지는 파이프라인을 만든다.

```text
뉴스 수집 -> 이슈 선별 -> 기사/이미지 확장 수집 -> 이미지 중복 제거 -> 글 작성 -> 자동 검증 -> 네이버 블로그 발행
```

수동 개입은 초기 설정과 장애 대응에만 둔다.

## 참고한 네이버 블로그형 패턴

예시 글(`blog.naver.com/yooju0913/224285137641`)은 다음 특징을 가진다.

- 제목이 `인물 + 사건/변화 + 클릭 포인트` 구조다.
- 첫 문단에서 핵심 키워드와 독자가 궁금해할 변화를 바로 설명한다.
- 긴 뉴스 모음이 아니라 한 이슈만 깊게 다룬다.
- 구분선과 짧은 소제목을 반복해 모바일에서 읽기 쉽다.
- 이미지가 여러 장 들어가고, 본문은 이미지 사이를 설명하는 흐름으로 이어진다.
- 마지막에는 관련 해시태그를 넉넉히 붙인다.

## 포스트 구조

각 포스트는 아래 구조를 기본으로 한다.

1. 제목
   - `인물/작품 + 실제 이슈 + 궁금증/변화 포인트`
   - 예: `신동 위고비 실패 후 근황 공개, 얼굴선 달라졌다는 반응 나온 이유`

2. 첫 문단
   - 검색 핵심 키워드를 자연스럽게 포함한다.
   - 누가, 어떤 일로, 왜 화제가 됐는지를 바로 말한다.

3. 본문 소제목 3-5개
   - `무슨 일이 있었나`
   - `이 발언/장면이 주목받은 이유`
   - `관련 반응과 이후 일정`
   - `정리`

4. 출처
   - 원문 기사 링크를 하단에 남긴다.
   - 여러 기사에서 확인한 경우 대표 기사와 보조 기사 링크를 함께 둔다.

5. 해시태그
   - 12-20개 권장.
   - 인물명, 그룹명, 프로그램명, 사건 키워드, 연관 검색어를 섞는다.
   - 숨김 키워드나 무관한 인기 태그는 사용하지 않는다.

## 자료 수집 방식

기존 `collect_entertainment_news.py`는 이슈 후보 수집에 계속 사용하되, 최종 출력은 요약글이 아니라 개별 포스트 큐로 바꾼다.

각 이슈마다 추가로 수집할 자료:

- 대표 기사 1개
- 같은 이슈를 다룬 보조 기사 2-5개
- 기사 제목/설명/발행시각/원문 URL
- 기사 `og:title`, `og:description`, `og:image`
- 공식 입장이 있으면 공식 입장 문장
- 방송/앨범/행사 일정이 있으면 날짜와 장소
- 네이버 블로그 검색 결과의 경쟁 글 제목 5-10개

본문에는 수집한 사실만 사용한다. 기사 원문 문장을 길게 베끼지 않고, 사실관계와 흐름을 새 문장으로 다시 쓴다.

## 이미지 전략

이미지는 네이버 블로그 유입과 체류시간에 중요하다. 다만 `뉴스 사진을 가져와서 조금 수정하면 괜찮다`는 전제로 운영하지 않는다. 크롭, 밝기 조정, 워터마크 제거, 색감 변경 같은 단순 편집은 저작권 문제를 해결하지 못한다.

따라서 자동화는 `이미지 수집 -> 중복 제거 -> 위험도 분류 -> 안전한 사용 방식 선택`으로 간다.

### 이미지 후보 수집

이슈마다 아래 출처에서 이미지 후보를 모은다.

- 기사 `og:image`
- 같은 이슈를 다룬 여러 기사 이미지
- 소속사/방송사/제작사 공식 보도자료 이미지
- 공식 SNS/유튜브 썸네일
- 네이버 블로그/포스트 경쟁 글의 이미지 패턴 참고
- 자체 생성 카드뉴스/타임라인/키워드 이미지

후보는 원본 URL, 출처 도메인, 이미지 크기, 파일 해시, perceptual hash, alt/title 문구, 기사 URL을 함께 저장한다.

### 중복 제거

여러 기사에서 같은 사진을 반복 사용하는 경우가 많으므로 아래 기준으로 중복 제거한다.

- URL 완전 일치 제거
- 파일 바이트 해시 일치 제거
- perceptual hash 유사도 기준으로 같은 사진 제거
- 같은 인물 사진이라도 크롭만 다른 경우는 하나만 남김
- 같은 기사사/같은 사진기자/같은 썸네일 계열은 우선순위 낮춤

최종 포스트에는 서로 다른 의미를 가진 이미지 2-4개만 사용한다.

예시:

- 인물 근황 사진 1장
- 방송/무대/작품 관련 이미지 1장
- 직접 만든 이슈 정리 카드 1장
- 타임라인 카드 1장

### 사용 우선순위

1. 안전 사용
   - 직접 생성한 대표 이미지
   - 공식 배포 자료 중 사용 허용이 명확한 이미지
   - 직접 캡처/제작한 표, 타임라인, 카드뉴스

2. 조건부 사용
   - 기사 `og:image`
   - 방송사/소속사/플랫폼 공식 썸네일
   - 유튜브 공식 영상 썸네일

3. 금지 기본값
   - 뉴스 기사 사진을 무단 다운로드해서 재업로드
   - 타 블로그 이미지를 복사
   - 출처만 쓰고 저작권 이미지를 재게시
   - 저작권 회피 목적으로 이미지에 약간의 편집만 가해 재사용

### 이미지 가공 원칙

이미지 가공은 저작권 회피가 아니라 블로그 콘텐츠 품질을 위한 편집이어야 한다.

허용:

- 직접 생성한 카드뉴스에 텍스트, 날짜, 키워드 추가
- 공식적으로 사용 가능한 이미지를 블로그 레이아웃에 맞게 리사이즈
- 자체 제작 타임라인/요약 카드/인물 정보 카드 생성
- 원문으로 이동하는 링크형 썸네일 카드 생성

비허용:

- 뉴스 사진을 가져와 색감만 바꾸기
- 얼굴이나 배경을 살짝 수정해 다른 이미지처럼 보이게 만들기
- 워터마크 제거
- 타 블로그 이미지를 저장해 재업로드

운영 기본값은 `이미지 후보 수집 + 중복 제거 + 위험도 표시 + 안전 생성 이미지 사용`이다. 기사 이미지를 재업로드하는 기능은 기본으로 끄고, 별도 승인 플래그가 있을 때만 후보로 남긴다.

### 운영 모드

이미지 사용은 현실 운영 수준에 맞춰 3단계로 나눈다.

#### `safe` 모드

기본값. 자동 게시까지 켤 수 있는 모드다.

- 자체 생성 대표 이미지/카드뉴스만 업로드
- 기사 이미지는 원문 링크 카드나 후보 목록으로만 보관
- 저작권 리스크가 가장 낮음

#### `review` 모드

초기 디버깅 모드. 자동 수집은 하되 업로드 전 사람이 고른다.

- 여러 기사에서 `og:image`와 본문 이미지를 수집
- 해시/perceptual hash로 중복 이미지 제거
- 같은 사진의 크롭/리사이즈 버전은 하나만 남김
- 공식 이미지, 뉴스 이미지, 블로그 이미지, 차단 이미지를 등급화
- 초안에는 이미지 후보와 출처 URL을 함께 표시
- 사용자가 선택한 이미지만 최종 업로드

#### `aggressive` 모드

목표 운영 모드. 운영자가 리스크를 감수하고 완전 자동화를 켰을 때 사용한다.

- 뉴스/기사 `og:image` 후보도 본문 이미지로 선택 가능
- 같은 이슈의 여러 기사에서 중복되지 않는 이미지를 2-4개 선택
- 이미지마다 출처 기사 URL과 원본 이미지 URL을 기록
- 워터마크 제거, 출처 은폐, 얼굴/배경 변형 등 회피 목적 편집은 하지 않음
- 리사이즈, 압축, 카드 레이아웃 삽입, 캡션 추가 정도만 허용
- 이미지가 부족하면 자동 생성 카드뉴스로 빈 자리를 채움
- 차단 이미지가 아니면 사람이 고르지 않아도 자동 선택

`aggressive` 모드는 네이버에서 흔히 보이는 방식에 가깝지만, 애드포스트가 붙어 있는 다른 블로그가 있다고 해서 권리 문제가 사라지는 것은 아니다. 이 모드는 설정 파일에 `image_mode: aggressive`가 들어 있을 때만 동작하게 만든다.

### 이미지 위험도 등급

- `safe`: 자체 생성 이미지, 사용 허용이 명확한 공식 배포 이미지
- `official_candidate`: 공식 SNS/방송사/소속사 이미지지만 사용 조건 확인 필요
- `news_candidate`: 기사 `og:image` 또는 뉴스 본문 이미지
- `blog_candidate`: 타 블로그 이미지, 재사용 금지 기본값
- `blocked`: 워터마크 제거 필요, 출처 불명, 연예인 사생활성 이미지, 선정적/자극적 이미지

완전 자동화 운영에서는 `safe`, `official_candidate`, `news_candidate`까지 자동 후보로 사용할 수 있다. `blog_candidate`는 기본 제외하고, `blocked`는 항상 제외한다.

`aggressive` 모드에서도 아래 조건은 자동 차단한다.

- 이미지 URL 또는 파일명에 워터마크/로고 제거가 필요한 흔적이 있음
- 본문 이미지가 아니라 광고/프로필/아이콘/스프라이트 이미지임
- 해상도가 너무 낮거나 심하게 잘린 썸네일임
- 사생활성, 선정성, 사고/범죄 현장성 이미지임
- 같은 포스트 안에서 perceptual hash가 이미 선택된 이미지와 너무 유사함

## 자동 게시 방식

네이버는 공식 오픈 API에 블로그 글쓰기 엔드포인트를 제공한다.

- 글쓰기: `POST https://openapi.naver.com/blog/writePost.json`
- 카테고리 조회: `GET https://openapi.naver.com/blog/listCategory.json`
- 인증: 네이버 아이디 로그인 OAuth access token 필요

따라서 자동화는 공식 API를 우선 사용한다. 단, 이미지 업로드나 스마트에디터 전용 기능이 API로 부족하면 브라우저 자동화로 전환한다.

초기 개발은 `dry-run`으로 검증하지만, 최종 목표는 `auto_publish`다.

```text
collect issue -> enrich article -> generate post -> validate -> publish -> log result
```

## 네이버 정책 리스크

네이버 블로그 운영정책은 기계적 패턴글 반복 게재, 검색 품질을 해치는 숨김키워드/히든태그, 저작권 침해를 제한 사유로 본다. 그래서 완전 자동화라도 아래 원칙을 지킨다.

- 같은 템플릿 문장을 매번 반복하지 않는다.
- 글마다 실제 이슈에 맞는 문장과 소제목을 만든다.
- 숨김 키워드, 무관한 태그, 과도한 반복 키워드를 넣지 않는다.
- 이미지 저작권이 불명확하면 재업로드하지 않는다.
- 민감 이슈는 보도 기준으로만 쓰고 단정하지 않는다.

## SEO 작성 기준

네이버 블로그용 SEO는 기술 메타태그보다 제목, 첫 문단, 본문 키워드 흐름, 이미지, 체류시간이 중요하다.

각 글은 아래 기준을 통과해야 한다.

- 제목에 핵심 인물/작품명과 이슈 키워드가 들어간다.
- 첫 2문장 안에 핵심 키워드가 자연스럽게 들어간다.
- 본문은 1,200-2,000자 정도를 기본으로 한다.
- 소제목은 3-5개로 나누고 모바일에서 읽기 쉽게 짧게 쓴다.
- 이미지 또는 카드형 시각 자료를 최소 2-4개 배치한다.
- 원문 링크를 남겨 신뢰도를 확보한다.
- 태그는 12-20개를 쓰되 실제 본문 이슈와 관련된 것만 쓴다.

## 구현 단위

1. `collect_entertainment_news.py`
   - 이슈 후보 수집과 점수화 유지.

2. `enrich_entertainment_issue.py`
   - 선택된 이슈별 기사 원문 메타, 보조 기사, 이미지 후보, 블로그 경쟁 제목을 수집.

3. `render_naver_blog_post.py`
   - 1개 이슈를 네이버 블로그용 HTML/Markdown/JSON으로 생성.

4. `create_naver_blog_images.py`
   - 카드뉴스/대표 이미지/본문 중간 이미지를 저작권 안전 방식으로 생성.
   - 이미지 후보의 해시/perceptual hash를 계산해 중복을 제거.
   - 이미지 위험도 등급을 붙여 자동 사용 가능 여부를 판단.

5. `validate_naver_blog_post.py`
   - 금칙어, 저작권 위험 이미지, 키워드 과다 반복, 출처 누락, 글자 수, 태그 수 검사.

6. `publish_naver_blog.py`
   - OAuth 토큰을 이용해 네이버 블로그 API로 게시.
   - API 이미지 업로드가 부족하면 브라우저 자동화 게시로 전환.

7. `run_naver_blog_automation.py`
   - 전체 파이프라인 실행기.
   - 날짜별 실행, 발행 개수 제한, 중복 발행 방지, 실패 재시도, 발행 로그 저장.

## 완전 자동화 설정

운영 설정은 `config/naver-blog-automation.json`에서 관리한다.

```json
{
  "mode": "full_auto",
  "image_mode": "aggressive",
  "publish_mode": "auto_publish",
  "posts_per_run": 5,
  "images_per_post": 3,
  "fallback_generated_images": true,
  "dedupe_images": true,
  "block_blog_images": true,
  "log_sources": true
}
```

자동 발행 전에 필요한 값:

- `NAVER_BLOG_CLIENT_ID`
- `NAVER_BLOG_CLIENT_SECRET`
- `NAVER_BLOG_ACCESS_TOKEN`
- `NAVER_BLOG_REFRESH_TOKEN`
- 네이버 블로그 카테고리 ID

값을 얻는 위치:

- `NAVER_BLOG_CLIENT_ID`: 네이버 개발자센터 > 내 애플리케이션 > 해당 앱 > 개요 또는 기본정보의 Client ID
- `NAVER_BLOG_CLIENT_SECRET`: 같은 화면의 Client Secret
- `NAVER_BLOG_ACCESS_TOKEN`: 네이버 로그인 OAuth 인증 후 `code`를 토큰 API로 교환해 발급
- `NAVER_BLOG_REFRESH_TOKEN`: 최초 토큰 발급 응답에 함께 포함
- `NAVER_BLOG_CATEGORY_ID`: access token 발급 후 `https://openapi.naver.com/blog/listCategory.json` 호출 결과에서 선택

로컬에서 토큰과 카테고리를 확인할 때는 아래 헬퍼를 쓴다.

```bash
python3 scripts/naver_blog_oauth_helper.py auth-url \
  --redirect-uri "http://localhost:8080/naver/callback"

python3 scripts/naver_blog_oauth_helper.py exchange \
  --redirect-uri "http://localhost:8080/naver/callback" \
  --code "CALLBACK_CODE" \
  --state "CALLBACK_STATE"

python3 scripts/naver_blog_oauth_helper.py categories
```

## 우선 결정할 것

- 사용할 네이버 블로그 ID
- 네이버 개발자센터 앱과 OAuth callback URL
- 자동 발행 개수: 기본 하루 5개
- 이미지 정책: `aggressive` 모드로 자동 수집/중복 제거/선택
- 발행 모드: 최종 목표는 `auto_publish`
